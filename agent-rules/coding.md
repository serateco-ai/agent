# 코드 수정

- 수정 대상과 기존 공용 컴포넌트·유틸·서비스·응답 및 예외 규약을 먼저 읽는다. 기술 스택을 파일명이나 기억으로 추정하지 않는다.
- 기존 경로·시그니처·필드명·에러 코드·라이브러리 로딩 경로를 보존한다. 호환성 변경이 요청 범위에 있으면 관련 호출부를 함께 수정한다.
- 같은 판정·필터·변환·검증은 공용 진입점 하나에 둔다. 채널 차이는 명시된 정책으로 표현하고 공통화 과정에서 차이를 없애지 않는다.
- 모듈 경계상 사본이 필요한 경우 적용 위치를 확인하고 함께 수정·검증한다. 한쪽만 고치지 않는다.
- 별칭·리소스 참조·스키마 등 서로 연결된 설정을 함께 갱신한다. 빌드가 통과해도 타입 검사나 실행이 깨질 수 있다.
- 예외를 삼켜 성공·빈 결과로 바꾸지 않는다. 비즈니스 오류 의미와 서버 메시지를 보존하고 일반 HTTP/전송 오류와 구분한다.
- 기존 암호화·직렬화·공용 빈을 재사용한다. 이중 암호화, 설정을 우회하는 별도 객체·사본을 만들지 않는다.
- 참조 0건만으로 삭제하지 않는다. 예정 기능·외부 호출·배치·의도된 예비 설정 여부를 확인한다.

## 소스 주석

- “왜 이 코드가 필요한가”만 쓴다. AI·에이전트·세션·사용자 지시·프롬프트·AGENTS/CLAUDE 문서 참조를 남기지 않는다.
- 가드 설명은 대상·처리·방지 목적 한 줄. 별표 강조·이모지·HTML 강조·겁박·긴 사고 서술을 넣지 않는다.
- 실명·계정·연락처·주소·개인 식별키는 마스킹본도 넣지 않는다. 운영 조사 건수·비율·성능 측정 수치도 소스 주석에 넣지 않는다.
- 설계 상수·한도·테이블/컬럼·원본 코드 위치·변경일은 허용한다. 상세 조사·근거는 프로젝트의 별도 기록에 둔다.
- 이 제한은 배포 소스/설정에 적용한다. 에이전트 지침 문서가 자신의 로딩 경로를 설명하는 것은 허용한다.
