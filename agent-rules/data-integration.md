# DB·외부 연동·분산 처리

- 원본 스키마·실제 쿼리/프로시저·규격서·최신 회신을 확인한다. 기억·요약·이전 에이전트 설명을 원문 대신 쓰지 않는다.
- 규격의 필드·값·상태·대소문자·단위·상한을 임의로 생략/축소/추측하지 않는다. 미정 항목은 문의/미확인으로 남기며 가짜 필드·키·엔드포인트로 메우지 않는다.
- 서로 다른 의미의 상태·날짜·주소·센터·사용자·집계 축을 합치지 않는다. 빈값/NULL/0/미변경의 뜻은 실제 계약을 확인한다.
- 기존 값·과거 스냅샷·공유 마스터를 한 건 처리 때문에 소급 변경하지 않는다. INSERT/UPDATE, 신규/수정, 채널별 가드 차이를 유지한다.
- 날짜 없음은 실제 스키마와 계약에 맞춰 NULL로 표현한다. 임의 센티넬 날짜를 새로 넣지 않으며 DB DEFAULT도 확인한다. 기존 레거시 값 조회 방어는 데이터 정리 없이 지우지 않는다.
- SQL·매퍼 컬럼 변경 시 정본 DDL·증분 DDL·실행본·관련 모듈을 함께 갱신한다. 구조 DDL과 실제 데이터 이관 SQL을 구분하며 개인정보가 섞인 파일은 Git 관리 소스에 두지 않는다.
- 테스트 시드는 실제 생성 규약과 같은 패턴을 따른다. 출처·테스트 여부·정리 방법을 명시한다. 규약이 불명확하면 임의 값으로 만들지 않는다.
- 외부 응답 성공·로컬 반영·실제 발송은 각각 확인한다. 영향 행 0건이 행 부재인지 무변경인지 구분한다. 오류·타임아웃을 정상 빈 결과로 숨기지 않는다.
- 재시도·폴링·웹훅은 멱등성·중복·역순·누락·상한을 고려한다. 요청량·재시도 횟수·대상 범위를 제한하고 실제 외부 규격에 맞춘다.
- 다중 인스턴스 환경에서는 공유 상태·전역 상호배제를 DB/공유 저장소·분산락·원자적 갱신으로 보장한다. 인스턴스 메모리·synchronized·Atomic만으로 전역 1회를 보장하지 않는다.
- 로컬 캐시·순수 계산은 공유 업무 상태와 구분한다. 파드별 캐시는 파드별로 갱신하며 한 파드의 분산락 갱신을 전체 캐시 갱신으로 착각하지 않는다.
- 정합성이 필요한 변경은 같은 트랜잭션에서 처리한다. 조회 후 갱신 분리는 경쟁 조건을 검토한다. 커밋 전 외부 호출·행 잠금·후속 이벤트의 순서를 확인한다.
- 독립적으로 진행돼야 할 상태·증빙·정산 단계는 실패/할 일 없음으로 서로 중단되지 않게 분리한다. 웹훅 수신과 무거운 처리도 분리한다. 불필요한 새 플래그·테이블을 만들기 전에 기존 저장처를 확인한다.
