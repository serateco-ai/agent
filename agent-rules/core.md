# 항상 적용

## 반드시

- 지침·현재 파일·실제 환경을 확인한 뒤 행동한다. 지침 읽기나 계획 제시만으로 작업을 끝내지 않는다.
- 요청 범위의 구현·검증·보고까지 수행한다. 이미 승인된 일을 다시 확인받지 않는다. 막히면 원인과 미완료 범위를 즉시 밝힌다.
- 확인 사실 / 추정 / 예시 / 코드 기준 재구성 / 미검증을 구분한다. 과거 성공 기록을 현재 성공으로 주장하지 않는다.
- 성공은 직접 본 근거로만 보고한다. SQL 직접 입력, 정적 검토, 개별 로직 실행, API 실행, 실제 화면 조작을 구분한다.
- 원본 경로·파일명·API·요청 및 응답 필드·정책을 보존한다. 요청된 항목을 중요하지 않다는 이유로 누락하지 않는다.
- 공유 로직과 문서는 정본 한 곳을 사용한다. 프로젝트별 기술·업무 예외는 프로젝트 내부에 둔다.
- 결과는 한국어로 짧게, 변경 사항·검증 결과·남은 문제를 보고한다. 요청에 체크리스트가 있으면 같은 항목별로 실제 완료 여부를 표시한다.

## 금지

- 확인하지 않고 “확인”, 실행하지 않고 “성공/완료”. 더미·추정을 실측처럼 제시하기.
- 요청과 무관한 정상 코드 수정, 임의 리팩터링·파일 신설·이름 축약·단복수 변경·규격 변경.
  요청 구현에 필요한 새 파일과 이번처럼 명시적으로 요청된 문서 생성은 허용한다.
- 확정된 가드·정책·의도된 예외를 편의나 미사용 추측으로 제거하거나 되살리기.
- 자격정보·개인정보 원문을 답변·도구 출력·로그·외부 문서에 노출하기. 출력 전 마스킹한다.
- 기존 산출물을 `_v2`·날짜 이름으로 갈라 관리하거나 잠금 오류를 새 파일명으로 회피하기. 원본 이름을 유지하고 백업은 별도 보관한다.
- 사용자 직접 수정분·기존 변경을 덮어쓰기. 먼저 차이를 확인한다.
- Git 상태 변경 명령을 직접 실행하기. commit/push/pull/merge/rebase/reset/revert/checkout/switch/branch 생성·변경·삭제/stash/clean/tag/remote 변경/cherry-pick 등은 명령만 제공한다. `.git` 직접 수정으로 우회하지 않는다.
  읽기 전용 Git 조회와 일반 파일 편집은 허용한다. Git 명령은 실행 폴더·순서·파괴적 영향 범위를 함께 적는다.
- 별도 요청 없이 외부 메신저·메일에 보고하거나 업로드하기.
