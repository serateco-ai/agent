# 빌드·운영·진단

- 실제 프로젝트의 실행 설정·스크립트·CI·인프라 문서를 기준으로 한다. 특정 프로젝트의 `.run`, Maven, Docker, 포트, 게이트웨이 구조를 다른 프로젝트에 강제하지 않는다.
- 코드가 이미지/번들에 포함되면 재빌드·재배포로 반영한다. 단순 프로세스/컨테이너 재시작을 코드 반영으로 착각하지 않는다.
- 기동 상태 + 시작/오류 로그 + 실제 API 동작으로 확인한다. 화면 영향은 ui.md를 따른다. 잘못된 포트·인증 없는 응답만으로 서비스 중지를 단정하지 않는다.
- 컨테이너 이름·노드 배치·환경·프로파일·설치 버전은 실제 조회한다. 서버명·오래된 배치 기록을 현재 상태로 단정하지 않는다.
- 로그는 최신 파일부터 끝부분 50~200줄로 시작하고 시각·요청 ID로 좁힌다. 실시간 콘솔과 영속 rolling 로그를 구분하며 이전 컨테이너 이력도 확인한다. 출력 전에 민감값을 마스킹한다.
- 설정 변경은 선언 파일·생성 단계·실제 실행 프로세스/연결까지 확인한다. 따옴표·인코딩·길이·실제 지원 옵션·환경변수 우선순위가 달라질 수 있다.
- 날짜는 업무 시간대·브라우저 로컬 시간·DB 연결 세션을 확인한다. 서버 기본 시간대만 보고 모든 값이 같다고 단정하지 않는다.
- 성능은 동일 조건·워밍업·여러 회차로 비교한다. 재시작 직후 메모리 감소·한 번의 측정·현재 순간값을 장기 효과나 peak로 보고하지 않는다.
- 측정 환경·기간·부하 모양·병목 근거·미검증 범위를 적는다. 단일 인스턴스 시험으로 다중 인스턴스 정상이라 주장하지 않는다.
- 설정 변경·실제 반영·원격 배포를 구분한다. 기존 백업·복구 절차와 의존 순서를 지킨다. 운영 반영·외부 전송은 요청에 포함된 범위에서만 수행한다.
