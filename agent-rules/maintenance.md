# 규칙 유지

- 공통 규칙은 이 폴더, 특정 프로젝트의 기술·업무·경로·실측·미해결 이슈는 해당 프로젝트 내부에 둔다.
- 매번 읽을 핵심은 core.md에만, 작업별 조건은 주제 파일에만 둔다. INDEX와 진입점은 링크와 적용 조건만 유지한다.
- 새 규칙 전에 기존 주제를 검색하고 정본 한 곳을 수정한다. 같은 문장을 진입점·색인·여러 주제에 복제하지 않는다.
- 문장은 한국어로 짧게, `적용 조건 → 행동/금지 → 완료 기준`이 분명하게 쓴다. 긴 사례·대화·로그·원문은 필수 로딩 문서에 넣지 않는다.
- 규칙 추가/정정 때 인덱스와 관련 참조도 갱신한다. 활성 규칙에는 최신 결론만 두고 정정 이유·이력은 maintenance/에 남긴다.
- 번호가 필요하면 파일별 고유 식별자를 쓴다. 중복 절 번호만으로 인용하지 않는다.
- 새로운 프로젝트 지침에는 공통 규칙 복사 대신 이 루트 색인의 위치와 프로젝트 상세 차이만 둔다.
- 공통 규칙 로딩 경로는 지침 파일 위치 기준으로 작성한다. 드라이브·사용자 계정·루트 폴더명을 고정하지 않는다. 분석 출처의 과거 절대경로는 실행 경로로 사용하지 않는다.
- 검증: 모든 로컬 링크가 존재하고 조건별 로딩이 연결됐는지, 최신 정정과 옛 규칙이 동시에 활성화되지 않았는지, 개인정보·프로젝트 전용 값이 공통 규칙에 섞이지 않았는지 확인한다.
