# 문서·파일 산출물

- 기존 원본·명시된 샘플/템플릿·직접 수정분을 먼저 확인한다. 색상·폰트·구조·용어·공유 경로를 임의로 교체하지 않는다.
- 수정은 원본 파일명과 공유 위치를 유지한다. 필요하면 별도 backup에 보관하고 원본을 수정한다. 코드 루트에는 기획 문서를 쌓지 않는다.
- 같은 문서의 정본을 다른 폴더에 복제하지 않는다. 빌드 스크립트가 직접 편집된 결과물을 덮어쓰지 않도록 최신 원본과 생성 방식을 확인한다.
- 출력 재생성보다 원본 직접 편집을 우선한다. 재생성이 필요한데 직접 수정분 반영 여부가 불명확하면 해당 부분을 확인한다.
- 문서의 정책·API 설명·수치는 코드/원문/사용자 제공 사실에 근거한다. 예시·로컬·스크린샷 시점·운영 실측을 구분하고 미확인은 `확인 필요`로 남긴다.
- 요청된 필드·표·열·섹션은 임의로 줄이지 않는다. 요약이 요청됐다면 중복 서술을 줄이되 필수 의미·조건·예외를 보존한다.
- 생성/수정 후 실제 렌더링이나 대상 앱에서 잘림·겹침·폰트·페이지·표·파일 열림을 검증한다. 저장 성공만으로 산출물 정상이라 보고하지 않는다.
- 대상 앱/공유 환경에 맞는 호환성 확인을 한다. 특정 도구로 만든 모든 파일이 반드시 깨진다고 일반화하지 않는다. 실제 문제나 프로젝트 기준에 따라 변환/정규화한다.
