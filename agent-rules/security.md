# 보안·개인정보

- 비밀번호·계정 자격·API 키·토큰·서명값·암호화 키·개인키는 도구 출력 전부터 제외한다. `.env` 전체 출력, 비밀값이 찍히는 grep, 원문 로그 전달을 하지 않는다.
- 기본 보고는 키 이름 + 존재 여부. 비교는 해시, 필요한 경우 길이를 사용한다. 부분값이 꼭 필요할 때만 앞 8자 이하, 8자 이하 값은 앞 2자 이하로 마스킹하고 뒤/중간은 공개하지 않는다.
- 시크릿 파일을 저장소 밖·동기화 폴더·외부 도구에 복사/업로드하지 않는다. 조사 전달은 파일 경로·라인·키 이름·위험도만 준다.
- 개인정보는 서버 응답·로그·감사 저장·다운로드 등 전체 경로에서 정책에 맞춰 보호한다. 화면에서만 가리지 않는다. 업무상 원문이 필요한 예외는 프로젝트에 명시된 권한·사유·감사 절차로만 처리한다.
- 마스킹된 표시값이 원본 DB를 덮어쓰지 않게 한다. 암호문도 로그에 그대로 남기지 않는다.
- 인증과 권한/데이터 소유 검증을 구분한다. 버튼 숨김은 권한 통제가 아니다. 조회·변경·취소·다운로드 API도 서버에서 판정한다.
- 공개 요청의 사용자 ID·채널·정책 우회 플래그를 신뢰하지 않는다. 신원은 인증 컨텍스트, 정책은 서버의 신뢰 가능한 자료로 결정한다.
- 개인정보를 로그/여러 업무 테이블에 불필요하게 복제하지 않는다. 삭제 정책과 업무 이력 보존을 함께 검토한다.
- 실제 개인정보·회원 식별값·수신번호를 테스트 기본값이나 커밋 대상 로컬 설정에 넣지 않는다. 환경 주입과 식별 가능한 테스트 데이터를 사용한다.
- 외부 발송·결제·실데이터 변경 테스트 전 실제 대상과 격리를 확인한다. “로컬이니까 안전”이라고 추정하지 않는다. 격리가 확인되고 작업 범위에 있으면 검증을 진행한다.
